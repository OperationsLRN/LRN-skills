# Lessons Learned — api-designer

## 2026-05-16 — Initial implementation

- **mitmproxy2swagger fills 80% of the spec automatically** — the generated spec has correct paths, methods, and request/response shapes from real traffic. The main manual work is: filling `FIXME` operation IDs, adding auth scheme, and writing descriptions. Budget 30 min review per 20 endpoints.

- **Instruct the client to exercise edge cases during capture** — auth flows (login/logout/refresh), error paths (404, 401, validation errors), pagination, and file uploads. Traffic not captured = endpoint not in spec. Give the client a checklist before they start mitmproxy.

- **Greenfield: max 2 nesting levels** — standard convention: `/v1/resource/{id}/sub-resource` is the limit. Never `/v1/a/{id}/b/{id}/c`. Enforced by `validate_rest_conventions()`.

- **Greenfield: version from day one** — always prefix with `/v1/`. Clients who skip versioning regret it when the first breaking change lands.

- **GraphQL = skip mitmproxy2swagger** — the tool generates REST specs only. For GraphQL reverse-engineering, introspect the schema directly: `curl -X POST <url> -d '{"query":"{ __schema { types { name } } }"}'`. Draft the SDL manually from introspection output.
